# 2026-11-21: the reader sends a Referer, and a refused page can open in the browser

DiveMeets answers event results and dive sheet pages with 403 and an empty page when the request has no
Referer, and with the page when the Referer is any DiveMeets page. This is DiveMeets' own rule, not
Cloudflare's check. The hidden browser sent none, so Results showed "Couldn't reach DiveMeets".

Maintainer's ruling: send a Referer as a browser does when you tap a link, plus a backup.

- The reader sends the DiveMeets page it got last as the Referer (the first page of a run sends none).
  Live mode's service browser sends the screen reader's last page too.
- When DiveMeets still refuses a page (a 4xx that is not its check), the screen says so in plain words and
  offers "Open DiveMeets in your browser", which opens the page the link came from. Opening the refused
  page itself there is refused the same way, so the person taps through from the page before it.
- This is not getting around the bot check: it is the header every browser sends.
