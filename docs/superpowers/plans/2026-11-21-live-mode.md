# Live meet mode and "Up next" alerts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A parent opens an event's live board from the meet page, taps Follow live, and gets "N divers away" and "up next" alerts with the screen off.

**Architecture:** A new parser reads DiveMeets' live board. Pure functions count the divers before each followed diver and pick which alerts are due. A `LiveProvider` above the screens follows the board through the existing live service (`useLivePage`), sends alerts through a new `Notify` context that the reader provides from `modules/live-reader`, and stops when the event closes.

**Tech Stack:** Expo SDK 58, React Native 0.88, Expo Router, TypeScript strict, Jest, Kotlin (Expo module), node-html-parser, zod.

**Spec:** `docs/superpowers/specs/2026-11-21-live-mode-design.md`

## Global Constraints

- Layers: reader → parsers → scoring → screens; screens (and `src/live.tsx`) never import the reader (`npm run check:layers`).
- Never faster than every 30 seconds; the service floor stays.
- No new production dependency. Alerts go through `modules/live-reader`; permission through React Native's `PermissionsAndroid`.
- Plain words, touch targets of at least 48, `accessibilityLabel` on every control, text that scales (AGENTS.md "Done means").
- Tests read saved pages from `fixtures/divemeets/` only; failing test first.
- Every check passes: typecheck, lint, test, check:layers, check:licenses, check:fixtures, check:skills, Android build in CI.

## Review Focus

- A board where the followed diver is not on it (followed someone in another event): no alerts, no card, no crash. Test in Task 2.
- The same board read twice (the 30-second reload with nothing new): no repeat alerts. Test in Task 2.
- The board has no Next Diver box (between rounds or before the event starts): count reads as unknown, no alerts. Test in Task 2.
- Alert permission refused: Follow live still runs, the screen says alerts are off. Test in Task 5.
- The live board stops being reachable mid-follow (NotReachedError): keep the last board, say "trying again", keep following. Test in Task 4.

- Create: `src/live.tsx`, `src/__tests__/live-state.test.tsx`; Modify: `src/app/_layout.tsx`, `src/__tests__/fixtures.ts` (a `withLive` helper giving a fake `FollowPage` and `Notify`)

**Interfaces:**
- Consumes: `useLivePage`, `NotifyContext`, `parseLiveBoard`, `alertsDue`, `diversBefore`, `useFollows`.
- Produces:
  ```ts
  LiveProvider({ children })
  useLive(): { path?: string; board?: LiveBoard; error?: Error; updatedAt?: number; away: number;
               start(path: string): void; stop(): void; setAway(n: number): Promise<void> }
  ```
  `away` is saved under AsyncStorage key `alertAway`, default 3, clamped 1 to 5.
  Status copy: title `` `Following ${name}` `` (first followed diver on the board, else the event name); text `Up next`, `` `${k} divers before them` `` (`1 diver`), `Dived this round`, or `` `Round ${current} of ${total}` ``.
  End copy: alert title `` `${eventName} is over` ``, text `` `${name} placed ${place}.` `` for each followed diver on the board joined with a space, or `Final results are on DiveMeets.`.
  Check copy: alert `DiveMeets wants a check` / `Open DiveData to carry on.`, sent once per check.
